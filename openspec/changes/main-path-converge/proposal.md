# Proposal: main-path-converge

## Why

验证脊柱与周边能力已基本齐：聊、出题、开考/回讲/深挖、门禁、再练、收工、
冷启动、面试升温。继续加机制收益低；学习者负担与活跃 OpenSpec 夹数在涨。

下一阶段默认：**收摩擦、藏机制、归档规格**——让「打开 → 过一关」比昨天更顺，
而不是再长高脊柱。

## What changes

1. **归档已落地的活跃 change**（机制/抛光已进 main 的夹），活跃表只留本波次
   与真正未完项。
2. **主路径摩擦审计 + 收敛**：固定走一遍
   `打开 → 今日焦点/空态 → 出题 → 去开考 → 过门芯片`，只改文案、空状态、
   断点、多余入口；不改 gate / 排程公式。
3. **工程概念继续躲用户**：设置/聊天不新增开发者台；机制无感则不暴露 UI。
4. **一张「当前主路径」说明**（短）：写进本 change 的 `design.md` 或
   `docs/SYSTEM.md` 一小段，方便人和 Agent 对齐「现在真相」。

## Out（本波次明确不做）

- 新垂直能力（第二大脑、完整 APPLY 工作流、工业 FSRS/CAT、面试 OS）
- 设置里加 Harness / 题参 / 门禁调参面板
- 自动 adopt prompt、全量 MCP 挂进聊天
- 多用户 / OAuth
- 为打磨而改 Critic / gate 阈值（除非主路径 bug）

## Success

- 活跃 `openspec/changes/*/` 明显变少（已 ship 的已归档）
- 主路径走通时，无「下一步是什么」的卡点；工程黑话不挡日常
- 无新的「能力说明书式」设置页

## Impact

- 主要：`web/` 文案与空态 / 断点；OpenSpec archive；`docs/SYSTEM.md` 短同步
- 次要：极小 API 文案字段（若有）；**不**扩 core 算法面
