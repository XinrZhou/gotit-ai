## 一句话

**Got it? Prove it.**  
gotit 是一个**愿意天天打开的学习与面试搭子**：陪你聊、记得你的弱点，并在该较真的时候较真——**没过关就不算会**。

聊天是表面，**验证是脊柱**。不是无头刷题流水线，也不是只会加油的聊天框。

---

## 为谁、解决什么

**为谁：** 需要持续学习、备考或面试准备的个人（当前单用户）。

**日子里的麻烦：**

1. **假懂** — 笔记翻过、课听过，一问就糊；自己也说不清到底会不会。  
2. **今天碰什么不清楚** — 打开工具就懵，或东抓一点西抓一点。  
3. **挂过的点会忘** — 两周前错的，再遇到还错；没有人帮你记「栽在哪」。  
4. **面试和学习两张皮** — 日常积累用不上，临阵才慌着抠项目。  
5. **工具两个极端** — 要么鸡血催得烦，要么只会陪聊从不较真。

**要帮你做到的事：**

- 打开就知道**今天还欠什么**，能一键开练。  
- 有人陪，但到点会**认真考你**；过没过靠证据，不靠感觉。  
- 挂了不白挂：**下次还会碰到**，并带着上次的教训。  
- **日常学习和面试深挖同一套标准**——会就是会，不会就是不会。  
- 态度是搭子不是监工：**催考有分寸**，不羞辱、不刷屏。

## 我们是 / 我们不是

| 我们是 | 我们不是 |
|--------|----------|
| 学习 + 面试准备的**验证型搭子** | 第二大脑 / 笔记仓库 |
| 对话里完成「聊 → 考 → 记住」 | 无头刷题机、只有 API 没有陪伴 |
| 掌握由**规则门**裁定 | 模型随口说「你学会了」就算过 |
| 人格稳定、分工清楚（谁考、谁讲、谁抠项目） | 为可爱而可爱的娱乐人设 |
| 可选地推送到微信等渠道 | 渠道本身不是产品；核在应用内 |

## 不可妥协（硬约束）

扩功能时**不得削弱**下列约定：

1. **Verified = done** — 信心 ≠ 证据；没过门就不算掌握。  
2. **掌握终审是确定性逻辑（代码）** — 可以有考官、复核，但最终档位（过了 / 还差点 / 欠着下次）不能单靠某个模型说了算。  
3. **失败有用** — 未过关要留下可再用的痕迹（队列、轨迹、弱点关系等），不能考完就丢。  
4. **上下文要省着给** — 再练时带「相关教训」，不要把整本笔记塞进模型。  
5. **人格服务判断，不服务表演** — 人设稳定是为了评分尺度稳定，不是 Cosplay。  
6. **主产品在应用内 Companion** — 外部渠道只是可选触达，不能把能力只做在渠道侧。

## 温度（软约束）

产品要有温度，但**不浮夸**：

- 默认是**稳伙伴**：记得弱点与节奏；你召才验，不无故施压。  
- 结果用语诚实（还差点、欠着下次），**不嘲讽、不鸡血**。  
- 提醒与推送**可关、可合并、不刷屏**。  
- 文案与界面克制；空状态也说人话，不堆概念。

若「更 AI」「更好看」和「更愿意天天打开 / 更经得起检验」冲突，**优先后者**。

---

## 能力脊柱（现在与始终围绕的）

所有功能应能挂上其中至少一条：

```text
今日焦点（欠什么 / 计划）
    → 陪伴对话（问得清、人格稳）
    → 验证（考我 / 回讲 / 项目深挖）
    → 门（过了 / 还差点 / 欠着下次）
    → 写回（轨迹 · 再练 · 弱点关系）
    → 下次更好（带教训、排得合理）
```

形态可以不同（聊天里考、工作流里考、提醒里点进来考），**掌握标准必须同一套**。

## 后续演进思路（按问题，不按炫技）

> **2026-08 当下默认：** 把「有温度的较真」做成可感日课——空态主动作、深挖诚实、
> 过关芯片可感（见 `openspec/changes/main-path-converge/design.md` 验收 S1–S5），
> 而不是再长高脊柱或 Agent 平台。机制诱惑进 Later。

演进只回答日子里还没被很好解决的问题。优先级从高到低：

### 1. 搭子更能办事（少让你点来点去）

- 能自己去看今日计划 / 欠账，帮你开练、记下该记的。  
- 工具要少而准、做了什么说得清；对话里用可点的结构块办事，少翻菜单。  
- *仍服务脊柱：办事是为了更顺地把验证跑完，不是为了展示「会调工具」。*

### 2. 「下次练什么、什么时候练」更老实

- 方向：结合**学习科学**（间隔复习、易混、可选轻量前置依赖），让排程和再练对象**可解释**。  
- 大模型继续负责出题、讲解、对话；**排程与掌握档位不交给模型随口定**。  
- *这是「LLM × 学习科学」交叉兴趣的产品落点，不是另起一个辅导产品。*

### 3. 更认得你、仍省上下文

- 跨天的弱点、易混、失败教训要能回来；注入保持预算。  
- 学习档案保持轻量：在啃什么、卡在哪——不为画像而画像。

### 4. 节奏有温度的触达（可选加强）

- 早/晚轻轻提「今天还欠几道」；临近面试可略加强项目深挖。  
- **今日收工**：欠清或用户主动收工时温和复盘，不无限催下一轮。  
- 永远可关；合并推送，禁止刷屏。

### 5. 外部输入最终要过关

- 资讯/推送里觉得「有用」的，应收成**可检验主张**，进计划或欠练，再走同一套门。  
- 不做泛资讯站或第二大脑；进不了「会不会」链路的输入默认不做。

### 6. 第一周就跑通证据链

- 空库或几乎空库时，引导走完：笔记 → claim → 开考 → 过门芯片/轨迹。  
- 目的是愿意天天打开，不是说明书式 onboarding。

### 7. 验证形态跟主张走

- 适合「讲不清就不算会」的，口说回讲应走**同一套 Critic + 确定性门**（可转写）。  
- 项目深挖服务面试准备；**默认不算掌握过关**（除非日后明确接同一终审）。  
- 临近面试时，今日焦点可偏深挖提示——催练可以，叙事上勿与「过了」混谈。

### 8. 用你自己的使用痕迹做小步改进

- 允许小规模固定题 / 前后对照，用来改排程或文案。  
- 目的是产品更准、更好用，不是对外刷榜。

## 新功能准入（Agent / 人扩需求时用）

**建议做**，当且仅当同时满足：

1. 能明确对应上文某一「日子里的麻烦」或脊柱链路中的一环；  
2. 不削弱「硬约束」；  
3. 做完后用户**更愿意打开**或**更难假装会了**（至少占一条）；  
4. 能用一两句人话说清「这和陪聊 / 假懂有什么关系」。

**默认不做**（易跑偏）：

- 第二大脑、通用笔记库、知识管理大而全；  
- 为热点而热点的能力（与假懂 / 再练 / 陪伴无关）；  
- 用模型替换掌握终审；  
- 娱乐向人设、社交、多用户协作；  
- 把主能力只做在外部渠道、应用内反而变空；  
- 与「会不会」无关的仪表盘堆砌。

拿不准时：先写清「解决哪条日常麻烦」；说不清就先不做。
